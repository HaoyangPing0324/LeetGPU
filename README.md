## Project Structure

```text
LeetGPU/
├── assets/
│   ├── common/
│   └── <problem_name>/
├── problems/
├── src/
│   ├── cuda/
│   ├── triton/
│   └── pytorch/
├── test/
│   ├── cuda/
│   ├── triton/
│   └── pytorch/
├── result/
│   ├── cuda/
│   │   ├── history.md
│   │   └── <problem_name>.txt
│   ├── triton/
│   │   ├── history.md
│   │   └── <problem_name>.txt
│   └── pytorch/
│       ├── history.md
│       └── <problem_name>.txt
├── doc/
├── scripts/
│   ├── .env.example
│   ├── run_cuda_remote.sh
│   ├── run_cuda_remote.ps1
│   ├── run_triton_remote.sh
│   ├── run_triton_remote.ps1
│   ├── run_pytorch_remote.sh
│   └── run_pytorch_remote.ps1
├── .gitignore
└── README.md
```

- `assets/`: Images and other resources used by challenge descriptions.
- `problems/`: Challenge descriptions from LeetGPU.
- `src/`: Implementations written in PyTorch, CUDA, and Triton.
- `test/`: Test code for validating each implementation.
- `result/`: Independent run outputs and execution history for each implementation.
- `doc/`: Shared solution documents for each challenge.
- `scripts/`: Reusable scripts for running challenges on a remote server.

## Environment Setup

Create an environment file from the provided example.

Linux:

```bash
cp scripts/.env.example scripts/.env
```

Windows PowerShell:

```powershell
Copy-Item scripts/.env.example scripts/.env
```

Open `scripts/.env`, update the server address, username, paths, and other required settings for your environment. Set `REMOTE_OS` to `windows` or `linux` for the target server, and then run the appropriate script.

## Script Usage

Complete the environment setup before running a script. Pass the problem name as the only argument. Use the Bash scripts on a Linux client and the PowerShell scripts on a Windows client.

Linux client:

```bash
bash scripts/run_pytorch_remote.sh <problem_name>
bash scripts/run_cuda_remote.sh <problem_name> [method]
bash scripts/run_triton_remote.sh <problem_name>
```

Windows PowerShell client:

```powershell
.\scripts\run_pytorch_remote.ps1 <problem_name>
.\scripts\run_cuda_remote.ps1 <problem_name> [method]
.\scripts\run_triton_remote.ps1 <problem_name>
```

The scripts support all four client/server operating-system combinations:

- Linux client to Linux server
- Linux client to Windows server
- Windows client to Linux server
- Windows client to Windows server

The author has validated CUDA, Triton, and PyTorch from a Linux client to both Windows and Linux servers. All four client/server operating-system combinations are implemented; the Windows client workflows have not yet been validated end to end by the author.

The optional CUDA `method` argument selects a named implementation when a challenge provides multiple CUDA optimization stages. Without it, the challenge's default implementation is used. Run histories always record correctness and timing when available, together with an optional problem-specific performance metric such as GFLOPS or effective GB/s.
